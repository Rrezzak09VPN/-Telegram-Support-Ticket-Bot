# 🎫 Telegram Support Ticket Bot

Простой и удобный Telegram-бот для организации технической поддержки через **тикеты** и **Telegram Topics (форум-темы)**.

---

## 🚀 Что умеет бот

✅ Создание тикетов пользователями через личные сообщения боту

✅ Автоматическое создание отдельной темы (Topic) в Telegram-группе для каждого тикета

✅ Переписка между пользователем и администраторами без раскрытия контактов

✅ Отправка текста, фото, документов, видео, голосовых сообщений, кружков и стикеров

✅ Закрытие тикетов пользователем или администратором — **с пометкой кто именно закрыл** прямо в названии темы

✅ **Постоянное нижнее меню-кнопки** у юзера и у админа (`ReplyKeyboard`) — не нужно каждый раз писать `/start`

✅ **Меню `/` возле скрепки** — команды бота регистрируются автоматически (`set_my_commands`)

✅ Система банов и разбанов пользователей

✅ Ограничение спама (Rate Limit) — сообщения, **суточный лимит тикетов** и **cooldown** между тикетами

✅ Ограничение размера файлов

✅ Автоматическая ротация логов

✅ Автоматические резервные копии базы данных

✅ Автозапуск через systemd

✅ **Reconcile при рестарте** — бот сверяет открытые тикеты в БД с темами в Telegram, помечает закрытыми те, чьи темы удалили / закрыли вручную

## 🆕 Что изменилось в свежей версии

- 🔒 Жёсткий антиспам на создание тикетов: `MAX_TICKETS_PER_DAY` (по умолчанию **5** тикетов / 24 ч) + `TICKET_CREATE_COOLDOWN_MINUTES` (по умолчанию **15** минут между созданиями).
- 🪪 В названии темы теперь видно `@username` **и** числовой ID одновременно: `🎫 #26 | @alice (123456789)`.
- 🏷 При закрытии тикета имя темы маркируется инициатором:
  - `🔴 👤 #26 | @alice (123456789)` — закрыл пользователь;
  - `🔴 🛠 #26 | @alice (123456789)` — закрыл администратор;
  - `🔴 🗑 #26 | 123456789` — тема была удалена руками, авто-чистка `reconcile`.
- 🗃 В БД появились колонки `tickets.closed_by` (`user` / `admin` / `system:*`) и `tickets.closed_by_user_id`. Миграция выполняется автоматически при старте бота — старые данные не теряются.
- 🎛 Нижнее меню-кнопки:
  - юзер: `🆕 Новый тикет` · `📋 Мои тикеты` · `🎫 Меню` · `ℹ️ Помощь` (если есть открытый тикет, появляется `🔴 Закрыть тикет`);
  - админ: `🔧 Админка` · `📊 Статистика` · `📋 Тикеты` · `📜 Баны` · `ℹ️ Помощь`.
- 🔎 Команда `/menu` — открывает меню в любой момент. `/admin` — панель администратора.
- ♻️ Reconcile на старте: помечает в БД `closed` те тикеты, чьи темы удалили / закрыли вручную в группе, и переименовывает оставшиеся открытые темы к новому формату.
- 🛠 Установщик при повторном запуске **обновляет код**, **сохраняет** конфиг и **дописывает** недостающие новые ключи в `config.env` без перезаписи существующих значений.

## 🖥 Установка

```bash
curl -sL https://raw.githubusercontent.com/Rrezzak09VPN/-Telegram-Support-Ticket-Bot/main/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh
```

Установщик автоматически:

* Установит Python (≥ 3.10) и зависимости
* Создаст виртуальное окружение
* Настроит systemd
* Создаст базу данных SQLite (с новыми колонками)
* Настроит резервное копирование (ежедневно в 03:00, хранит 14 копий)
* Настроит logrotate
* Запустит бота

При установке спросит **6 параметров** (раньше было 4):

1. `BOT_TOKEN`
2. `GROUP_ID` (принимает числовой ID, ссылку `https://web.telegram.org/k/#-...` или `https://t.me/c/.../...`)
3. `ADMIN_IDS` (через запятую)
4. `PROJECT_NAME`
5. `MAX_TICKETS_PER_DAY` (по умолчанию **5**)
6. `TICKET_CREATE_COOLDOWN_MINUTES` (по умолчанию **15**, `0` = выключено)

## 🔄 Обновление (с предыдущей версии)

Запустите тот же скрипт ещё раз:

```bash
curl -sL https://raw.githubusercontent.com/Rrezzak09VPN/-Telegram-Support-Ticket-Bot/main/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh
```

Установщик:

* Обнаружит существующую установку и предложит обновиться.
* Скачает свежий `bot.py` и обновит зависимости.
* **Не тронет** ваш `config.env` — только допишет недостающие ключи (`MAX_TICKETS_PER_DAY`, `TICKET_CREATE_COOLDOWN_MINUTES`) с дефолтными значениями в отдельный комментированный блок `# === Добавлено миграцией ... ===`.
* Перезапустит сервис.
* `bot.py` при старте сам выполнит миграцию схемы БД (`ALTER TABLE tickets ADD COLUMN closed_by ...`), reconcile открытых тикетов и регистрацию команд `set_my_commands`.

## ⚙️ Как работает бот

1. Пользователь пишет боту в личные сообщения — снизу появляется **постоянное меню-клавиатура**.
2. Нажимает **«🆕 Новый тикет»** (или `/start` → инлайн «Создать тикет»).
3. Бот создаёт новую тему (Topic) в Telegram-группе с именем `🎫 #N | @user (id)`.
4. Все сообщения пользователя автоматически попадают в эту тему.
5. Администратор отвечает прямо в теме группы — ответ уходит пользователю в ЛС.
6. После решения вопроса тикет закрывается:
   * пользователем → тема переименовывается в `🔴 👤 #N | @user (id)`, в БД `closed_by='user'`;
   * админом (кнопка «🔴 Закрыть» под сообщением) → `🔴 🛠 #N | @user (id)`, в БД `closed_by='admin'`.
7. Если кто-то удалит/закроет тему вручную в группе — при следующем старте бота `reconcile` это заметит и пометит тикет закрытым в БД.

## 📋 Что потребуется

### 1️⃣ BOT_TOKEN

Токен Telegram-бота. Получить можно у [@BotFather](https://t.me/BotFather) командой `/newbot`.

После создания бота BotFather выдаст токен вида:

```text
123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Вставить в:

```env
BOT_TOKEN="ВАШ_ТОКЕН"
```

⚠️ Также в [@BotFather](https://t.me/BotFather) рекомендуется выключить `/setprivacy` (Privacy Mode → **Disable**), чтобы бот видел сообщения админов в темах группы.

---

### 2️⃣ GROUP_ID

ID Telegram-группы, где будут создаваться тикеты.

⚠️ Группа должна быть:

* Супергруппой
* С включёнными **Topics** (Темами)
* Бот должен быть **администратором** с правами `Manage topics`

Пример:

```env
GROUP_ID=-1001234567890
```

Установщик принимает не только числовой ID, но и ссылку из веб-клиента (`https://web.telegram.org/k/#-...`) и ссылку `t.me/c/...`.

---

### 3️⃣ ADMIN_IDS

Telegram ID администраторов. Узнать свой ID можно через [@userinfobot](https://t.me/userinfobot).

Один админ:

```env
ADMIN_IDS=123456789
```

Несколько админов:

```env
ADMIN_IDS=123456789,987654321
```

---

### 4️⃣ PROJECT_NAME

Название проекта, отображаемое в сообщениях бота.

```env
PROJECT_NAME="🚀 Support Bot 🌐"
```

---

### 5️⃣ MAX_TICKETS_PER_DAY 🆕

Максимум тикетов от одного пользователя за **последние 24 часа** (считаются все тикеты, включая закрытые — это блокирует цикл «создать-закрыть-создать-...»).

```env
MAX_TICKETS_PER_DAY=5
```

Рекомендуется **3–10**. При превышении пользователь получит:
> ⚠️ Лимит 5 тикетов в сутки исчерпан (5/5). Попробуйте через 7 ч 23 мин.

---

### 6️⃣ TICKET_CREATE_COOLDOWN_MINUTES 🆕

Минимальный интервал между созданиями тикетов одним и тем же пользователем.

```env
TICKET_CREATE_COOLDOWN_MINUTES=15
```

* `0` — выключено.
* Рекомендуется **10–15** минут.

Считается от `MAX(created_at)` всех тикетов пользователя. При попытке создать новый тикет до истечения cooldown:
> ⚠️ Подождите 12 мин 30 сек перед созданием следующего тикета.

## 🗃 Схема БД (для админа)

Таблица `tickets`:

| Колонка             | Тип       | Описание                                                   |
|---------------------|-----------|------------------------------------------------------------|
| `id`                | INTEGER   | Номер тикета, PK                                           |
| `user_id`           | INTEGER   | Telegram ID автора                                         |
| `username`          | TEXT      | Username автора на момент создания                         |
| `status`            | TEXT      | `open` / `closed`                                          |
| `topic_id`          | INTEGER   | `message_thread_id` темы в группе                          |
| `created_at`        | TIMESTAMP | Время создания                                             |
| `closed_at`         | TIMESTAMP | Время закрытия                                             |
| `closed_by`         | TEXT 🆕   | `user` / `admin` / `system:no_topic` / `system:topic_deleted` / `system:topic_closed_manually` |
| `closed_by_user_id` | INTEGER 🆕| Telegram ID того, кто нажал «закрыть» (0 для system)       |

Полезный запрос для аналитики:

```sql
SELECT closed_by, COUNT(*) FROM tickets
WHERE status='closed'
GROUP BY closed_by;
```
